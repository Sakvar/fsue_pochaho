# Монетизация и коммерческий контур (черновик)

Документ описывает **намеренную** модель для браузерной / Telegram-версии «ФГУП ПОЧАХО» без обязательства немедленной реализации платёжного backend.

## Продуктовая модель: Telegram-first freemium

1. **Бесплатный вход:** базовый сценарий («Классика 1983») как демонстрация механики и тона.
2. **Прогрессия:** дополнительные сценарии открываются за мета-условия (завершения, архивные отметки) — без оплаты за «победу за деньги», чтобы не ломать нарратив.
3. **Платный слой:** дополнительные сценарии, расширенный архив концовок, косметика интерфейса, ранний доступ к контенту — **не** продажа игровых ресурсов как преимущества.

## Каналы монетизации

| Канал | Роль |
|--------|------|
| **Telegram Stars / встроенные платежи** | Основной кандидат для Mini App: низкий порог входа пользователя, единая среда. |
| **Внешние донаты (Boosty, Patreon, «Купить кофе»)** | Быстрый старт без интеграции SDK: ссылка из экрана «Поддержать». |
| **itch.io / отдельный «Deluxe»-билд** | Для аудитории вне Telegram: PDF, артбук, саундтрек. |

## Техническая вилка: честный unlock vs сервер

### Вариант A — честный локальный unlock (MVP)

- После оплаты пользователь получает **ссылку** или одноразовый код, клиент записывает флаг в `localStorage` (через Zustand `persist`).
- **Минусы:** технически подделываемо; подходит для доната и «supporter»-косметики, где жёсткая защита не критична.

### Вариант B — валидация на сервере (рекомендуется для платного сюжета)

- Минимальный backend (бот + Cloudflare Worker / Vercel function): проверка Telegram `initData`, выдача подписанного JWT или короткоживущего токена доступа.
- Клиент хранит только **результат** проверки, а список купленных пакетов — на сервере.
- **Плюсы:** сложнее обойти; можно обновлять контент независимо от билда.

### Telegram Stars (контур без полной реализации сейчас)

1. Бот принимает оплату / Stars.
2. Backend фиксирует `user_id` + SKU.
3. Mini App при старте запрашивает статус доступа (или получает подпись в deep link).
4. Контент премиум-сценариев подгружается только при положительном статусе (или остаётся в билде, но закрыт флагом с сервера).

## Аналитика и ценообразование

Без событийной аналитики (`game_start`, `card_choice`, `scenario_change`, `ending`, `support_click`) невозможно обоснованно резать воронку. Эндпоинт задаётся `VITE_ANALYTICS_ENDPOINT`; см. README.

## Риски

- Любой **только клиентский** premium обходится через DevTools.
- Рост объёма контента — отдельный трек от платежей; см. README, подсекция про платный релиз.

## Резюме

Для первого коммерческого шага разумна связка: **внешняя ссылка на донат** + **честный unlock** для косметики; параллельно проектировать **Worker + Telegram** для платных сценариев, если метрики это оправдают.
