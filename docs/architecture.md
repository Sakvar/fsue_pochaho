# Архитектура прототипа

Главный принцип: симуляция не зависит от Phaser.

```text
src/
  content/              # текстовые названия и будущие JSON-каталоги контента
  game/                 # Phaser-сцены, ввод, рендер
  simulation/           # чистое игровое ядро
```

## Simulation

`src/simulation` хранит состояние мира и игровые системы:

- `types.ts` — типы сущностей;
- `createInitialWorld.ts` — стартовая карта, сотрудники, контракты и пул найма;
- `pathfinding.ts` — поиск пути по сетке;
- `mapEditing.ts` — строительство стен и дверей, зоны, пересчёт маршрутов;
- `contracts.ts` — доска контрактов, аванс/выплата/штраф;
- `economy.ts` — бюджет, зарплата, запчасти, модернизация станка, архетипы;
- `hiring.ts` — найм кандидатов;
- `people.ts` — смены, авто-усталость, мораль/стресс, больничные, посты;
- `quality.ts` — качество заготовок, риск дефекта, ОТК и репутация;
- `equipment.ts` — износ, запчасти, ТО/ремонт и журнал обслуживания;
- `rng.ts` — детерминированный ГПСЧ для симуляции;
- `simulation.ts` — основной tick, генерация задач, назначение сотрудников, выполнение работ.

Симуляция отвечает за жизненный цикл контракта, бюджет, сроки, износ оборудования и
диагностику причин простоя. HUD получает готовый список производственных проблем
через `getProductionIssues`. Игрок принимает контракты, нанимает людей, назначает
смены/посты, покупает запчасти, модернизирует Р-17 и списывает брак через API симуляции.

Эта часть должна оставаться тестируемой без браузера и без Phaser.

## Game

`src/game` отвечает только за отображение и ввод:

- рисует карту, стены, помещения, сотрудников и станки;
- показывает состояние задач;
- передаёт команды игрока в simulation-слой.

## Следующий технический шаг

Перед усложнением игры стоит вынести рецепты, профессии, помещения и станки в data-driven формат, чтобы добавление контента не требовало переписывать симуляционные системы.
