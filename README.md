# ФГУП «ПОЧАХО»

Браузерная нарративная игра про закрытый советский институт: бинарные решения, ресурсы, флаги последствий, локальное сохранение и PWA.

## Требования

- Node.js 20+ (рекомендуется 22)

## Установка и запуск локально

```bash
npm install
npm run dev
```

Сборка и предпросмотр продакшн-бандла:

```bash
npm run build
npm run preview
```

Тесты:

```bash
npm test
```

## Демо и скриншоты

- **Публичный демо-URL:** задайте в описании деплоя (например GitHub Pages: `https://<user>.github.io/<repo>/`) после первой выкладки.
- **Скриншоты для витрины:** добавьте изображения в каталог [`docs/screenshots/`](docs/screenshots/) (каталог можно создать при подготовке релиза) и при желании вставьте ссылки в README.

## Переменные окружения (Vite)

Задаются при сборке (`VITE_*` встраиваются в клиент):

| Переменная | Назначение |
|------------|------------|
| `VITE_ANALYTICS_ENDPOINT` | Необязательно. URL для POST JSON с событиями (`game_start`, `card_choice`, `scenario_change`, `ending`, `support_click`). См. [`src/analytics.ts`](src/analytics.ts). Сервер должен разрешать CORS с вашего origin. |
| `VITE_SUPPORT_URL` | Необязательно. Ссылка «Поддержать объект» на экране «О проекте» (кнопка в подвале). Если не задана, кнопка не показывается — только пояснение в тексте. |
| `VITE_CLARITY_PROJECT_ID` | Необязательно. [Microsoft Clarity](https://clarity.microsoft.com/) — записи сессий и тепловые карты. ID проекта из настроек Clarity; скрипт подключается в [`src/clarity.ts`](src/clarity.ts). |

## PWA

После `npm run build` сервис-воркер и манифест генерируются в `dist/`. В режиме разработки PWA может вести себя иначе; проверяйте установку через `npm run preview` или продакшн-деплой.

## Telegram Mini App

Приложение может работать и как обычный сайт, и как Telegram Mini App:

- В браузере всё остается без изменений.
- В Telegram автоматически включается режим Mini App (инициализация WebApp, окно разворачивается, подхватываются `themeParams`, haptic feedback на выборе решения, шеринг исхода через `openTelegramLink` при наличии API).

Как подключить:

1. Задеплойте фронтенд на HTTPS-домен (GitHub Pages подходит).
2. В `@BotFather` настройте кнопку запуска Mini App (`/newapp` или `/myapps`) и укажите URL деплоя.
3. Откройте Mini App из Telegram — приложение само определит окружение и включит Telegram-режим.

## Деплой на GitHub Pages

1. Создайте репозиторий (например `owner/fsue_pochaho`). Имя репозитория влияет на `base` Vite: в CI выставляется `GITHUB_REPOSITORY`, и приложение собирается под путь `/<имя-репозитория>/`.
2. Включите GitHub Pages: **Settings → Pages → Build and deployment → GitHub Actions**.
3. Пуш в ветку `main` запускает [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml): тесты, `npm run build` с `GITHUB_REPOSITORY`, загрузка `dist` в Pages.
4. Если основная ветка не `main`, измените триггер в workflow.

Локально без префикса приложение доступно с корня (`base: '/'`). На Pages откройте URL вида `https://<user>.github.io/<repo>/`.

Тексты [`docs/legal/`](docs/legal/) подключаются в клиент при сборке (импорт `?raw`); отдельная копия в `public/` не требуется.

## Структура репозитория

- [`src/App.tsx`](src/App.tsx) — компоновка экрана, меню (сценарии, архив исходов), подвал с юридическими модалками и «О проекте»
- [`src/components/`](src/components/) — UI: ресурсы, карточка, досье, штамп, финал, шеринг исхода
- [`src/game/`](src/game/) — логика: стор, движок карт, концовки, эффекты, досье-тексты, аналитика вызовов из стора
- [`src/data/cardContent.ts`](src/data/cardContent.ts) — каталог карточек: константа **`CARD_CATALOG_SCENE_COUNT`** (сейчас **75** записей в `CARD_LIST`, включая мета-карточки из [`metaCardContent.ts`](src/data/metaCardContent.ts))
- [`src/data/characters.ts`](src/data/characters.ts) — персонажи
- [`src/data/endings.ts`](src/data/endings.ts) — условия и тексты исходов
- [`src/analytics.ts`](src/analytics.ts) — опциональная отправка событий на ваш endpoint
- [`src/clarity.ts`](src/clarity.ts) — опционально Microsoft Clarity (`VITE_CLARITY_PROJECT_ID`)
- [`docs/MONETIZATION.md`](docs/MONETIZATION.md) — стратегия монетизации и технические вилки
- [`docs/legal/`](docs/legal/) — политика конфиденциальности, соглашение, описание ассетов (подключаются в UI из исходников)
- [`src/styles/`](src/styles/) — глобальные стили и тема
- [`public/`](public/) — иконки PWA и favicon

## Монетизация и контент

Краткая стратегия (Telegram-first, freemium, без pay-to-win) и варианты с донатом vs серверной проверкой оплаты: [`docs/MONETIZATION.md`](docs/MONETIZATION.md).

**Контент для платного релиза:** для самостоятельной продажи «коробки» или крупного DLC разумно ориентироваться на заметно больший объём, чем в текущем MVP (порядка **120–200** карточек, **10–20** исходов, **5–8** сценариев, плюс мета-слой вроде архива и достижений). Текущий объём удобен для бесплатного демо и итераций.

## Roadmap (черновик)

- Расширение сценариев и скрытых веток
- Отдельный редактор контента (JSON/YAML) и валидация каталога
- Аудио-атмосфера
- Локализация интерфейса (EN) без потери русскоязычного тона карточек
- Опциональная ежедневная «директива» в Telegram (требует бота или статического календаря)

## Известные ограничения

- Прогресс хранится локально (`localStorage`); очистка данных браузера сбрасывает игру.
- Защищённый платный контент нельзя надёжно опирать только на клиент без серверной или Telegram-проверки покупки (см. `docs/MONETIZATION.md`).

## Идеи на будущее

- Аудио-атмосфера (телеграф, вентиляция, печатная машинка)
- Больше ветвлений и скрытых исходов

- Достижения и коллекция штампов (частично перекрывается архивом исходов в меню)
- Локализация интерфейса (EN) без потери русскоязычного тона карточек
